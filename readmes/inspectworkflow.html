inspectworkflow

A local viewer for Claude Code transcripts. You point it at a folder of .jsonl logs and read each one as a conversation instead of a wall of JSON, with subagent and workflow runs grouped by the folder they ran in.

The whole thing is server.py, which only uses the Python standard library, and index.html. The server listens on 127.0.0.1 only, the page doesn't load anything from the internet, and the one file it ever writes is containers.json, the list of folders you told it to watch. It never writes to a transcript.

Running it

You need Python 3.7 or newer and nothing else.

python3 server.py

Then open http://localhost:8792.

The sidebar starts empty. Drag a folder onto the page (a workflow folder, a session folder, or anything above them) and it gets watched and saved to containers.json, so it's still there the next time you start the server. The browser only gives the server the folder's name, not its full path, so the server looks for a folder with that name under ~/.claude/projects and picks the most recently changed match. To search somewhere else, pass those folders as arguments:

python3 server.py ~/work/logs ~/.claude/projects

If the name isn't found, the page reads the .jsonl files itself and opens them read-only without watching anything. Dropping single files works the same way. Each watched folder in the sidebar has an x that stops watching it.

Reading a transcript

Every row in the sidebar is one agent. The server guesses a title from what the run did, usually the file it wrote to most. If it didn't write anything, it falls back to a task line in the prompt, a file the prompt mentions, or the prompt's first sentence. When the guess is bad, double-click the row to rename it. Names are saved in the browser's local storage.

Above the transcript are toggles for each kind of event: thinking, tools, results, answer and prompt. Thinking, answer and prompt start on. Tools and results start off because they're a lot of noise unless you're tracking down a specific call. The filter box hides events that don't contain what you type and highlights the matches in the rest.

Under the toggles is a strip with one bar per event, scaled by length, so you can see the shape of the whole run at once. Click a bar to jump to that event. Alt+Left and Alt+Right switch between open tabs.

Following a live run

A background thread rescans the watched folders every second and pushes changes to the page over server-sent events on /api/stream. When a transcript you have open changes, the page asks for everything after the last byte it already has instead of reloading the file, so a run that's still writing grows in place. With follow on, which is the default, the view stays at the bottom unless you've scrolled up. A dot next to an agent means its file changed in the last 90 seconds.

To keep the sidebar quick, the server only parses the first 200 KB of each file as JSON (that's where the prompt, model and working directory are) and caches each agent until its file's size or modified time changes.

Settings

Variable Default What it does
INSPECTWORKFLOW_PORT 8792 Port to listen on
INSPECTWORKFLOW_MAX 300 How many of the newest transcripts to show
INSPECTWORKFLOW_VERBOSE unset Log every request to stderr
